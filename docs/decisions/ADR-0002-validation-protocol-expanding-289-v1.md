# ADR-0002 验证协议采用 expanding_289_v1

- 状态：accepted-provisional（依据交接文档的建议暂行采用；按授权矩阵，验证协议需要学生确认）
- 日期：2026-10-26
- 提出与执行：cursor/claude-opus-5.5（T-20261026-01）
- 学生复核：pending
- 取代：旧协议 `aie1903-chronological-289`（旧版 `configs/validation-plan.json`）

## 背景

旧协议有三个 fold：

| fold | 拟合段 | 预测段 | 备注 |
|---|---|---|---|
| fold_day4 | [0,1152) | [1152,1441) | |
| fold_day5 | [0,1440) | [1440,1728) | 截断为 288 步 |
| fold_last289 | [0,1439) | [1439,1728) | |

它的问题在于：

1. fold_day5 与 fold_last289 几乎完全重叠，fold_day4 与 fold_last289 也有重叠，各 fold 之间不独立；
2. fold_day5 只有 288 步，与官方的 289 步不一致；
3. 没有保留窗口，最后一段预测区间被常规开发直接使用。

旧协议只在 cell_30 上跑过一次季节朴素基线（`reports/legacy/`），没有经过调参。因此，cell_217 的最后一段至今没有被任何选择过程使用过。

## 决策

采用交接文档建议的 expanding_289_v1，写入 `configs/validation-plan.json`（这是工作区规则指定的路径）。索引从 0 开始，区间左闭右开，每个预测段都是 289 步，彼此不重叠，拟合段逐步扩展。

| fold | 拟合段 | 预测段 | cell_217 时钟 | cell_30 / grid_273 时钟 |
|---|---|---|---|---|
| dev_a | [0,861) | [861,1150) | 12-03 22:45 → 12-04 22:45 | 12-03 23:35 → 12-04 23:35 |
| dev_b | [0,1150) | [1150,1439) | 12-04 22:50 → 12-05 22:50 | 12-04 23:40 → 12-05 23:40 |
| heldout | [0,1439) | [1439,1728) | 12-05 22:55 → 12-06 22:55 | 12-05 23:45 → 12-06 23:45 |
| final | [0,1728) | 官方测试 289 行 | 12-06 23:00 → 12-07 23:00 | 12-06 23:50 → 12-07 23:50 |

- 常规开发只用 dev_a 和 dev_b。
- heldout 要等模型和选择规则都冻结，并经学生批准后才评估；评估过就要记录，此后它不再是 untouched。
- 当前 heldout 的状态：**untouched**，按项目协议从未被评估过。

## 已知局限

- 只有 6 天数据，无法估计周效应。
- dev_a 的拟合段只有 861 行。直接多步监督（289 步目标）时，回看长度最多约为 861 − 289 = 572。
- 三个验证起点的日内时刻（22:45、22:50、22:55）与官方测试起点（23:00）相差 1 到 3 步。这是在 1728 行内既要 289 步不重叠、又要保留窗口时，不可避免的妥协。
- 只有 2 个开发 fold，方差较大；结论要看两个 fold 是否一致，不能只看均值。

## 备选方案

- **继续使用旧协议**：fold 重叠，也没有保留窗口，不采用。
- **把起点对齐到 23:00**（索引 864、1152、1440）：最后一个窗口会越过 1728，或者相邻窗口重叠，不采用。
