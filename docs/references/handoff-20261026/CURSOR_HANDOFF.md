## 1 先理解本轮范围

用户准备先用 Cursor 完善学校服务器上的项目基础，之后让 Grokbot 登录同一学校环境并调用 Claude Code 持续开发。本轮应交付真正可用的基础，不以目录、空文件或概念方案代替实现。

你可以在已明确的项目工作区内自主读取、诊断、补文档、修改代码、创建隔离环境、补齐官方公开数据并运行短小的 CPU 验证。不要每建立一个文件或修复普通缺项都请求确认。先完成不依赖额外权限的工作；只有影响工作区之外、已有他人任务、额外付费资源、秘密信息外传、公开发布或正式竞赛提交的动作，才另行处理相应授权。

本轮不做大规模模型研究、长时间调参、自动榜单提交或全天候训练。只做基础设施及必要的基线验收。已经存在的模型、实验、代码和未提交改动都要保留并识别。

这份文档不是服务器现状报告。编写者没有登录该服务器，不能确认项目路径、已有文件、GPU、数据集或软件已经齐全。你必须实测并记录。文中课程事实、用户已知信息、建议方案和未决事项应保持区分。

## 5 评分与验证协议

### 5.1 指标必须统一实现

所有官方指标数值越低越好。每份提交同时计算五项，各指标独立排名。没有已核实的综合加权总榜或名次换分公式。

- MAE：所有测试位置的绝对误差均值。
- RMSE：所有测试位置的平方误差均值开平方。
- 小区 MAPE：所有位置的绝对相对误差均值，再乘 100。
- 网格 MAPE：仅真实值大于 0 的位置参与均值，再乘 100。
- 小区 Masked MAPE：门槛分别为真实值至少 300000、1000000。
- 网格 Masked MAPE：门槛分别为真实值至少 10000、100000。

所有掩码由真实值决定，不能按预测值决定。对保留的全部位置直接计算平均，不默认先给每条序列算 masked 平均再等权平均，否则不同有效数量会改变指标。记录各项计入数量；没有有效位置时返回可解释的空结果和 count=0，不能伪装为误差零。不要随意加 epsilon 改变官方 MAPE 的零值规则。

217 PDF 的 masked 公式分母写 n，但文字说筛选外位置不参与平均；cell/grid PDF 用筛选后的 n′。没有正式评分代码时，本地按“保留位置的平均”实现，明确记录 provisional 定义，核对评分代码后再冻结版本。MSE、log 尺度损失与原尺度官方分数不能混称。

### 5.2 推荐的开发协议

若现有协议未经用户确认或没有合法协议，可采用下面的版本 `expanding_289_v1`。索引从 0 开始，区间左闭右开。

- 开发 A：训练 `[0,861)`；预测 `[861,1150)`，289 点。
- 开发 B：训练 `[0,1150)`；预测 `[1150,1439)`，289 点。
- 保留窗口：训练 `[0,1439)`；预测 `[1439,1728)`，289 点。
- 最终：全部 1,728 行拟合后预测官方测试 289 行。

三个验证区间不重叠，历史逐步扩展。常规开发命令只使用 A/B；保留窗口需显式选择，选型后再评估。基础验收不需要消费保留窗口。若此前已经用它调参，诚实记录它已不是 untouched holdout，不为获得“干净”标签而删记录。

本协议是建议，用户已确认的现有合法协议应保留。模型输入太长导致早期折没有合法训练样本时，调整 lookback 或另建有版本的协议，不能偷用后续标签。

### 5.3 任何代理都不得违反的时间边界

- 每折标准化、异常阈值、分组、相关矩阵、特征选择及融合权重只能从该折训练部分学习。
- 监督样本的全部目标必须落在允许训练区间，不能只按输入起点切分。
- 预测 289 步期间，禁止向模型注入验证或测试的真实中间流量。
- lag 1、lag 288、邻居、父小区、共同因子都要检查信息时间。未来关联流量只能用合法预测，不能用未来真值。
- 第 289 点的一日前真值已经落到预测区间。日周期基线应周期延拓最后 288 点，或使用更早已知的同刻历史，并有测试证明未越界。
- 不用包括隐藏测试段在内的全量统计估计模型参数或调预测尺度；数据说明中的全量分位数和峰谷只作为背景。
- 六天历史不足以可靠学习一周规律；匿名编号不代表真实地理邻近。

数据路径、输出根、设备、线程与随机种子都通过配置/CLI 设置，不散落硬编码。外部挂载数据可以通过配置引用，不为了统一目录复制大量数据或移动仍被运行任务引用的路径。

复用已可用的隔离环境与依赖管理。新环境优先参考 starter 的 Python 3.11+，但实际服务器镜像兼容性需要验证；不要覆盖学校预装环境、sudo 升级全局软件或盲目升级 CUDA。锁定实际验证过的项目依赖；CPU/GPU 若有不同解析，分别记录。

基础阶段用最少必要依赖：数据处理、基础数值、配置、测试和绘图即可。已有 PyTorch 可审计；不为未来可能使用的模型一次性安装所有框架。不引入数据库、Web 服务、复杂队列或整套实验平台作为本轮必须项。

## 8 代理规则如何统一并确认生效

### 8.1 一份共享行为约定

`AGENTS.md` 保存简洁的项目入口与关键约束；`docs/agent-contract.md` 保存详细执行流程。课程事实放在 `docs/project-context.md`，机器参数放配置，真实状态放 `docs/current-status.md`。不要把所有内容复制进三套指令，形成互相冲突的版本。

先把共享文档建立为真实文件，再安装指令入口，避免新指令要求读取尚不存在的路径。已有上级指令、用户修改和只读材料约束必须保留；合并现有规则，不整文件覆盖。不更改全局 Cursor/Claude 配置来让本项目规则生效。

### 8.2 AGENTS.md 必须覆盖的内容

- 开工先确认根目录、读取背景、行为约定、当前状态和任务卡。
- 六天历史、289步、288日周期、真实标签边界及五指标。
- 不编辑原始数据与课程原件，不造成绩或补测试标签。
- 每个有意义的改动任务留记录，每次运行产生可追踪的 run_id。
- 同一工作树只有一个活跃写入者；不得停止不归自己管理的任务。
- 常规工作自主推进，涉及工作区外、额外资源或发布的边界按用户授权处理。
- 完成后运行相应检查，更新状态、改动和待办，报告实际证据。

### 8.3 CLAUDE.md 是 Claude Code 入口

Linux 上使用准确大小写 `CLAUDE.md`。若已有 `claude.md`，先辨别内容与使用方式再合并，不保留两份相互矛盾的指令。

推荐创建一个短文件，开头使用真实导入语法：

```markdown
@AGENTS.md

## Claude Code 工作入口

先读取 docs/project-context.md、docs/agent-contract.md、docs/current-status.md 及当前任务卡。
从项目根运行已验证的项目命令；按共享约定记录改动、实验、失败和交接状态。
```

不能只假设 Claude 会自动读取 `.cursor/rules`。`@AGENTS.md` 要写在真实 CLAUDE.md 正文中，不放在反引号或代码块中。不要用循环导入，也不要用全局秘密文件作导入来源。

### 8.4 .cursor/rules 使用可识别的格式

规则文件扩展名为 `.mdc`，包含 YAML frontmatter；普通 `.md` 不是等效规则。建议每个规则控制在约 50 行，详细说明引用共享文档。

- `00-project.mdc`：`alwaysApply: true`，关键约束和开工读取顺序。
- `10-forecasting.mdc`：适用于实际源码、测试和配置路径，记录时间边界、指标与数据语义。
- `20-records.mdc`：`alwaysApply: true`，任务、改动、运行和状态的记录要求。
- `30-server.mdc`：适用于实际运行代码、脚本和配置，说明设备、持久化、进程和资源预算。

具体 `globs` 必须匹配整理后的真实路径。核心约束直接放在 alwaysApply 规则，不假设一个 `@文件名` 会自动展开全文。若已有 `.cursorrules` 或其他等价规则，整合后说明迁移，不叠加互相冲突的旧规则。

包内 `templates/` 的文件名带 `.template`，只是参考模板，不应原样拷贝后宣称已激活。Cursor 需在正式项目合并内容、移除末尾 `.template` 并核对实际路径。模板不是可以直接批量覆盖现有文件的脚本。

### 8.5 验证实际加载

在新 Cursor 会话确认 alwaysApply 与按路径规则处于适用状态；在真实 Claude Code 会话确认项目 CLAUDE.md 与共享指令被加载。Claude 官方提供上下文查看方式，具体随安装版本核对，不为了验证而强制全局升级。

让每个工具在不修改文件的情况下回答：当前赛道、预测长度、日周期、禁止的未来信息、记录位置和运行边界。答案应对应实际共享文件；把检查方法和结果记录到 audit。

规则文本是模型上下文，不是强制的系统隔离。配合真实的配置验证、路径检查、数据哈希、运行元数据和测试；不能承诺“写好指令就绝不会误操作”。不要为此擅自启用新的全局 hooks 或放宽权限。

## 9 改动与实验必须留下什么记录

### 9.1 以任务记录有意义的改动

每个有意义的任务创建一个 task_id，记录目标、范围、执行者、基准代码版本、计划、实际改动、验证命令与结果、风险、下一步。小的关联修改可合并为一项，不要求每改一行都重复写日志。

Git diff 保存逐行变化；`CHANGELOG.md` 按任务简述为什么改、改了什么、验证结果，链接任务卡。`docs/current-status.md` 保留最新可用命令、当前赛道、最近任务/运行、已知阻塞和下一步。已有内容可续写，不把历史清空。

任务执行者如实写 Cursor、Grokbot、Claude Code 或具体组员。人工尚未复核就写 pending，不能替用户签署“已审核”。`docs/ai-use-log.md` 记录重要 AI 贡献、人工修正与实际证据，不记录账号口令或大段私密对话。

### 9.2 每次运行是独立证据

每次 smoke、回测、训练或最终预测都生成唯一 run_id 与完整记录，至少包括：

- task_id、执行者、开始结束时间、状态与退出码。
- code_commit；若未提交，标记 git_dirty，并保存必要源码/差异校验以复现，不能冒称干净提交。
- dataset_id、文件来源和 SHA-256、有效数据合同版本。
- 完整解析后的配置快照、配置哈希、随机种子、环境依赖快照。
- 拟合与预测时间范围、验证协议和每折标识。
- 模型与训练损失、五指标、各掩码数量、原尺度或变换尺度说明。
- CPU/GPU设备、线程、实际墙钟时间、可测得的峰值内存/显存。测不到写 null 并说明，不能填零。
- 预测、图、日志和模型的路径及哈希；结论、失败原因与下一步。

运行开始即建立元数据，结束时补结果。中断、OOM、取消、超时和异常都记录，不只保存好看的运行。生成的 JSON 必须是严格 JSON；不适用的值用 null，不使用 NaN/Infinity 伪装数值。

完整产物放 `runs/<run_id>/` 的持久化位置；小型脱敏摘要进入 `reports/runs/` 和实验索引。说明这些信息如何备份和回传，不能将唯一记录留在临时容器盘。

本轮不要求复杂的审计系统，但要有一个实际可执行的检查，能发现缺少任务记录、配置快照、run 元数据或产物引用失效。它不能通过“自动补全空记录”把未完成事项变绿。

## 10 运行与 Grokbot 接手规范

用户此前报告 Grokbot 管理端为 Debian 13、8 核 Intel Xeon、16 GB 总内存、当时约 9.5 GB 可用、无独立 GPU、无 swap、128 GB 磁盘。该配置不代表学校服务器，且可用量会变化。学校端必须现场探测，管理端的当前余量也不能写成永久事实。

基础验收默认 CPU、单实验、少量线程、有限时长；资源预算写入 runtime 配置并真正传给运行代码。没有明确学校配额时，不启动长 GPU 实验、不占满所有核、不在后台无限重试。

后续 Grokbot 从已验收的项目根启动 Claude Code，先读取共享背景、当前状态与任务卡，确认没有另一个写入者或重复作业，再开展一个有预算的任务。不要仅凭聊天记忆决定当前版本。

同一工作树内，Cursor 完成本轮并交接后，Grokbot 才接手写入。需要多人并行时先设计隔离分支/工作树和合并方式；本轮不默认启用多个代理同时修改同一目录。

每个长任务记录 run_id、PID或学校 job_id、启动命令、日志和持久化路径。断线重连先查任务状态再恢复，不因没看到页面输出就重新启动。不能声称使用持久终端就能抵抗容器回收。

一个有界任务结束后，Grokbot 要读取真实指标与图、更新记录并输出简洁中文汇报，再提出下一批。后续实验原则上每批限制少量配置、时间/内存/提交预算；资源不足、核心失败重复或没有可解释改进时，保留诊断，不无休止重跑。

保存并核对产物后再释放属于自己且已结束的学校资源；已有作业未结束时不自动回收。VPN、SSH、端口转发或平台权限不在代码整理时擅自修改。原始数据与学校凭据不要自动发给外部模型，按实际课程授权的数据范围处理。

## 11 必须跑通的最小基础流程

复用现有接口；如果没有，提供统一 CLI。下面是目标能力，示意命令不是已存在的程序。你必须实现或映射等效接口，并在 README 填写实际上运行成功的命令。

```text
python -m aie1903.cli doctor
python -m aie1903.cli audit-data --dataset cell_217
python -m aie1903.cli fetch-data --dataset cell_217
python -m aie1903.cli backtest --config configs/baseline.yaml
python -m aie1903.cli predict --config configs/baseline.yaml
python -m aie1903.cli validate-submission --dataset cell_217 --input 实际预测CSV路径
python -m aie1903.cli verify-records
```

保留现有包名时可以换模块路径；不要为满足示例名称而重写整个项目。

- doctor：报告项目根、持久化、必要依赖、规则/配置、资源与可选 GPU 情况；必需缺项应有明确失败状态。
- audit-data：检查当前赛道的合同、哈希、训练/测试边界、空测试标签与必要映射，输出人可读和机器可读报告。
- fetch-data：仅补缺失或显式指定版本的已核实官方公开数据；不覆写用户原始文件。若数据已齐，可保留等效获取说明。
- backtest：对开发 A/B 或现有已确认合法协议跑日周期基线，记录每折五指标与全部元数据，默认不触碰保留窗口。
- predict：使用完整公开训练集一次输出真实 289 步预测，不填随机数。简单周期基线也可以作为本轮可运行实现。
- validate-submission：与对应官方 test 文件逐项核对时间戳、完整行列、顺序、数值有限和缺失；项目可默认产生非负预测，但区分“非负推荐”与官方明文的无效条件。
- verify-records：检查入口指令指向真实文件、配置可解析、任务/运行记录与产物对应，失败能被发现。静态检查通过不能代替运行过程序。

关键验证应覆盖：手算指标与掩码计数；网格零值是否正确排除；不同有效数量的全局平均；训练目标跨界；修改未来标签不会改变已训练特征与预测；第289步没有偷读真值；输出精确匹配测试文件；失败运行状态没有被标为成功。只做与这些核心风险有关的检查，不为无关格式变化编造大量测试。

至少跑一次真实主赛道开发回测和一次真实最终形状预测，通过格式检查。若主赛道尚无法获取，继续用可用官方赛道验证通用代码，并明确“主赛道数据阻塞”，不能把替代赛道通过说成主项目全部通过。

如已有 30 小区环境且准备迁移 217，可以先做 30 的短小检查，再做 217。若用户已经明确选择其他赛道，按实际选择验收。本轮不要求优化分数；需要的是一条真实可复现的基础流程。

## 12 按下面顺序执行并验收

1. 读取已有指令与状态，建立 initial audit、任务卡、回退依据，保护现有代码和运行。
2. 确认数据赛道、持久化、环境与依赖，报告并补齐本轮必需缺项。
3. 建立共享背景与行为约定，合并 AGENTS.md、CLAUDE.md 和 Cursor 规则；检查实际加载。
4. 整理配置、数据合同、运行记录和真实 CLI，保留可用旧接口并解释映射。
5. 完成关键检查、真实基线回测、289步预测和格式验证；确认失败状态及记录可追踪。
6. 更新 CHANGELOG、任务、当前状态与 Grokbot runbook，形成 final audit 和可移交摘要。

验收不能只看文件是否存在，必须分别给出：

- **已有并验证可用**：附真实命令、结果和证据路径。
- **本轮新增或修复并验证**：说明改动与验证。
- **存在但未验证**：明确原因。
- **缺失且阻塞**：说明依赖什么信息或权限。
- **可选未做**：例如网格扩展和大模型实验，不能假装是必需失败项。

## 13 最后给用户与 Grokbot 的交接内容

请用中文给出一份可独立阅读的完成报告，至少包含：

1. 实际项目根、当前分支/代码版本、选定赛道及真实数据状态。
2. 最终目录树，区分源码、配置、文档、原始数据和生成产物。
3. 原来缺什么、本轮补什么、还有什么没解决；不要把未验证内容写成可用。
4. AGENTS.md、CLAUDE.md、Cursor 规则如何共用约定，实际加载如何检查。
5. 从当前环境运行 doctor、数据审计、基线回测、预测、格式校验、记录校验的真实命令。
6. 首次运行的 run_id、每折五指标、时间和内存、预测CSV、图与日志位置。未得到的数值留空并说明。
7. 如何创建下一项任务、继续追加改动与实验记录，以及 Grokbot 从哪里读取状态。
8. 给 Grokbot 的一段开工指令，引用真实项目相对路径、已验证命令和运行预算。

如果全部基础验收通过，可以报告项目已具备进入有界开发迭代的条件。如果仍有核心阻塞，明确范围，并交付其他已完成部分，不把整个工作停留在等待授权或泛泛计划中。
