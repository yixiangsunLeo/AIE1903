# 路线图

每个里程碑开工时建任务卡，并按卡内的验收标准完成。本文件只列目标和验收要点，实际进度以 `docs/current-status.md` 为准。功能区的接口与不变量见 `docs/architecture.md` §4。

## 阶段 0：框架 ✅

已在 v0.2.0 完成，任务卡为 `T-20261026-01`。

内容包括：规则与指令文件、记录体系、功能区骨架、配置、数据完整性校验、Git 规范与 hooks、项目 venv。

## 阶段 1：可复现的基础流程

这一阶段对应交接文档 §11 要求的最小可运行流程，按顺序完成。

| 里程碑 | 涉及功能区 | 交付 | 验收要点 |
|---|---|---|---|
| **M1 数据层** | config、data | 配置加载与路径解析；`load_train` 和 `load_test_template`；合同校验；checksum 校验；`audit-data` 和 `fetch-data` | 能在三个数据集上复现 A-20261026-framework 的结论；一次只读一个数据集；没有读取 sample 数值的函数；不硬编码路径 |
| **M2 指标** | evaluation | 五项指标及计数；空 mask 输出 null/0；grid 的 MAPE 规则；`validate_submission` | 手算用例通过；不同有效数量时整体平均正确；grid 的 0 值被排除；能发现格式错误 |
| **M3 切分与守卫** | splits | 协议加载、fold 迭代；监督目标与特征源的越界检查 | 目标跨界时报错；heldout 默认不可见；第 289 步的 lag-288 被拒绝；fold 之间不重叠 |
| **M4 运行记录** | tracking | run_id；run.json 在开始和结束时写入；环境与哈希快照；实验索引；失败记录 | 失败运行不会被标为成功；严格 JSON；null 语义正确；索引与摘要一致 |
| **M5 基线回测** | models、pipelines | `seasonal_naive`（周期延拓）；`backtest` 跑 dev_a、dev_b | 先在 cell_30 上演练，再跑 cell_217；改动未来值不会改变预测；记录五项指标及计数、耗时和内存 |
| **M6 最终预测与提交校验** | pipelines、evaluation | `predict`（用 1728 行预测 289 步）；`validate-submission` | 输出与 test.csv 逐项一致（时间戳、列、顺序、有限值、无缺失）；基线正确性用训练数据自行验证，不与 sample 比对 |
| **M7 统一入口与自检** | cli、tracking | `doctor`、`verify-records`、统一 CLI | 能发现入口指令指向不存在的文件、缺失的配置快照和失效的产物引用；README 只写实际验证过的命令 |
| **M8 核心图** | viz | 序列概览与日周期叠加图；回测中预测与真值的对比图 | 图全部来自已记录的产物；选中的图复制到 `reports/figures/` |

完成 M1–M8 后打标签 `v0.3.0`。此时项目具备进入有界研究迭代的条件。

## 阶段 2：有界研究迭代

以下方向是建议，不是课程要求：

- 日周期加近期水平修正；
- 跨小区共享（低秩分解或聚类）；
- 对水平跳变做稳健处理；
- 统计模型（ETS、STL）；
- GBM 类模型；
- 小型 RNN 或 GRU；
- GP 的不确定性估计。

每一批实验都要满足：

- 任务卡写明预算，配置数量要少；
- 只用 dev fold 做选择；
- 模型冻结、并经学生批准后，才评估 heldout；
- 改进必须能解释，否则不保留。
